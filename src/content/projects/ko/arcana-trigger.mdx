## 동기

Arcana Trigger는 턴제 덱빌딩과 실시간 탑다운 슈팅을 결합한 게임입니다. 손패로 대응하기 어려울 때 직접 조준하고 탄막을 피하는 액션 전투로 전환하고, 액션 조작이 어려울 때는 카드 전략으로 전투를 풀도록 설계했습니다. 두 모드는 체력과 상태 이상을 공유하여 전환 후에도 같은 전투가 이어집니다.

**NHN Game × AI Hackathon 2026 예선 출품**을 위해 2인 팀으로 개발했습니다. 게임 AI 연구에서 다뤘던 관심을 실제 게임 규칙·인터페이스·진행 흐름의 구현으로 확장한 경험입니다.

[웹 데모 플레이](https://calendar3450.github.io/NHNAIGameProject/) · [소스 코드](https://github.com/calendar3450/NHNAIGameProject)

## 담당 구현

- **코어와 카드 전투:** 덱·손패·버린 카드·에너지·턴 처리, 공유 전투 상태, 카드/액션 세션 전환.
- **모드 간 규칙:** 장착 무기별 공격 카드, 공유 화상·둔화 효과, 적 행동 의도와 보스 카드 패턴.
- **절차적 던전:** 시드 기반 방·통로 생성, 연결성 검증, 장애물과 탐색 공개, 실제 게임 Scene 통합.
- **진행과 UI:** 카드 보상·제거, 전투 HUD, 층 전환, 무한 런 점수와 게임오버 결과.
- **통합과 검증:** 규칙·인터페이스 문서화, Scene 연결, Unity EditMode/PlayMode 집중 회귀 검증.

팀원은 이동·조준·사격, 적의 액션 행동과 탄막 패턴을 중심으로 담당했습니다. 공유 게임 규칙과 Scene 통합을 기준으로 협업했습니다.

## 구현 접근

턴제와 실시간이라는 서로 다른 시간 모델에서 하나의 전투 상태를 유지하는 것이 핵심 과제였습니다. 세션 수명주기와 상태 전환 규칙을 명시해 모드 전환 시 체력·상태 이상·보상이 일관되게 이어지도록 했습니다. 던전은 시드로 재현하고 연결성을 검사해 디버깅 가능한 구조로 만들었습니다.

## 개발·검증 과정

Unity 6/C#을 사용했으며, 2인 팀으로 WebGL 빌드를 GitHub Pages에 배포하여 웹 데모를 제공했습니다.

개발 과정에서는 Codex Desktop을 활용해 기능 명세 작성, 기존 코드 분석, 구현 계획 수립, C# 코드와 테스트 작성, 개발 문서 정리 및 오류 분석을 진행했습니다.

AI가 제안한 코드와 변경 사항은 개발자가 변경 내역을 검토하고, 플레이테스트·Unity Console 확인·EditMode/PlayMode 테스트 및 화면 검토를 통해 반영 여부를 판단했습니다.

개발 기록에는 런타임·콘텐츠·UI·Scene의 기능별 검증이 정리되어 있습니다. 다만 최종 빌드와 모든 브라우저 경로의 통과가 확인된 것은 아니며, 일부 기록에는 폰트·콘텐츠 테스트 실패와 수동·Web 검증 잔여 항목이 남아 있습니다.

## 결과와 배운 점

프로토타입을 출품했지만 **예선을 통과하지 못했습니다**. 게임 아이디어를 실제 전투 규칙·UI·절차적 콘텐츠·팀 통합으로 구체화한 개발 경험을 얻었습니다. 기능 구현, 자동화 검증, 플레이테스트, 최종 브라우저 검증을 각각의 완료 기준으로 관리해야 한다는 점도 배웠습니다.
